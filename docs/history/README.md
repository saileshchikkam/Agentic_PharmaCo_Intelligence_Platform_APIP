## Recording work

Use one `YYYY-MM-DD.md` per active date in the user's local timezone. Append a separate heading for each meaningful work session; keep earlier events intact. New real entries must be linked above. Do not pre-create future diary pages.

Each entry should state:

- Outcome and purpose.
- Product layer and affected paths.
- Concrete changes and decisions.
- Checks actually run, results, and unrun checks.
- Remaining limitations, blockers, and next action.
- Commit/issue links when available; the current commit is discoverable from Git history, so do not invent its hash before committing.

Plans and targets belong in the roadmap/research pages, not as completed diary events. Report failures and scope reductions honestly. Do not include private chat identifiers, credentials, patient narratives, or workstation paths.

Earlier template notes contained “Day 1” labels without reliable dates. Their useful mission and research content was consolidated into the product, decision, roadmap, and research pages; no calendar history has been fabricated.
