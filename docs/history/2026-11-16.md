## MedAssist Model A Phase A2.2 Stage 6: Recovery Worker PID 17880 Termination Investigation & Standalone Resumption Hardening

### Investigation of Termination Cause
- **Termination Analysis:** Worker PID 17880 terminated after successfully computing and committing batch 1 (ordinals 69,000–69,499) and batch 2 (ordinals 69,500–69,999).
- **Exact Exception:**
  `FileExistsError: [Errno 17] File exists: 'C:\\apip_research\\campaign_2026\\run_01\\stage6_recovery_progress.json'`
  in `models/medassist_v2/training/data.py:27` via `write_json`.
- **Root Cause:** The frozen helper `write_json` in `data.py` uses `open('x')` (exclusive creation mode). On the second batch write, `stage6_recovery_progress.json` already existed, triggering `FileExistsError`.
- **Committed Progress Preserved:** SQLite transactions commit *before* the progress JSON write. Verification query on `run_01\validation-trajectories.sqlite` confirmed:
  - Max ordinal: `69,999`
  - Distinct patients: `70,000`
  - Total trajectories: `280,000` (52.85% completion)
  - `PRAGMA integrity_check`: `ok` (100% clean).
  - All 280,000 trajectories were backed up to `C:\apip_research\campaign_2026\backup_20261116_0905\` (SHA-256: `9DB4C6F7CE7D1F530E1D1D7FB28FE86B25984A6B32310522701CBBCFF6FB85FD`).

### Fix Applied
- Replaced `write_json` calls in `scripts/recover_model_a_stage6.py` with `safe_write_json()`, which writes to a temporary file (`.tmp_<pid>`) and atomically replaces the target file (`tmp_path.replace(path)`).
- Ensured `campaign-provenance.json`, `pre-test-seal.json`, and `pre-test-seal-hash.json` are unlinked if present prior to final sealing to prevent any `FileExistsError` during the final provenance write.
