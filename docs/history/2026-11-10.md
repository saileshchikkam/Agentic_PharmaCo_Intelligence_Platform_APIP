# Development history - 2026-11-10

## Complete website demonstration, subpage navigation repair, and guest fixture isolation

- **Objective**: Deliver a complete, fully navigable website demonstration for university authorities across all implemented modules (Public Landing, Authentication Dialog, Patient Dashboard, ADR Guided Reporting, Saved ADR Cases, MedAssist AI Overview, Specialist Profile, Specialist Application Status, and Developer Reference) without requiring live Supabase credentials or blocking on authentication dialogs.
- **Root Cause Analysis of Subpage Blocker**:
  - `AccountProvider` previously evaluated `ready=true, user=null` for unauthenticated visitors, causing protected routes to trigger authentication redirects.
  - `APIPAuthDialog` mounted globally in `AccessPreview` had an unconditional `useEffect` post-auth redirect (`if (user && ready)`) which, combined with non-null guest users, triggered an infinite navigation loop (`/#/patient/home` replacing any target hash).
  - Subpage data fetchers in `CaseWorkspace.tsx` and `GuidedWorkspace.tsx` attempted live authenticated fetch calls to `/api/account/*` with fictional user IDs, encountering 25-second timeouts or 401 `SIGN_IN_REQUIRED`.
- **Implementation & Security Isolation**:
  - `src/features/account/AccountProvider.tsx`: Added typed fictional guest entities (`GUEST_PATIENT`, `GUEST_SPECIALIST`, `GUEST_PATIENT_PROFILE`, `GUEST_SPECIALIST_PROFILE`), extended `AccountState` with `isGuest: boolean` and `setGuestRole()`. Real Supabase sessions strictly take precedence over guest roles.
  - `src/features/access/AccessPreview.tsx`: Conditionally mounted `APIPAuthDialog` only when `isSignIn` is true. Auto-assigned guest role on demo routes when unauthenticated.
  - `src/features/account/APIPAuthDialog.tsx`: Guarded post-authentication redirect with `open && user && !isGuest && ready && mode !== 'reset'`. Added "Explore as Patient" and "Explore as Specialist" quick-action buttons for academic evaluation.
  - `src/features/adr/cases/CaseWorkspace.tsx`: Intercepted requests with `owner.startsWith('fictional-')` to return local synthetic case cards and drafts without making network requests.
  - `src/features/adr/guided/GuidedWorkspace.tsx`: Added an in-memory mutable `localGuestCase` state handler for `fictional-` owners, supporting interactive step-by-step reporting, field confirmation, and draft updates.
  - `src/features/specialist/SharingWorkspace.tsx`: Synthetic directory and inbox responses for fictional specialist evaluation.
  - `src/DeveloperReference.tsx`: Permitted developer design reference inspection when running in development or under `fictional-` guest mode.
- **Verification & Results**:
  - `npm run lint`: Clean TypeScript compilation with 0 errors across all modified modules.
  - `npm run build`: Production bundle succeeded in 4.82s (`dist/index-C21ruYDT.js`, 2412 modules).
  - Multi-viewport browser route verification: 11/11 routes confirmed PASS with verified rendered headings and content. Zero "Checking your account…" white screens or redirect loops.
  - Backend health (`http://127.0.0.1:3601/api/ready`): `ready: true`, `checks: { database: true, pdf: true, auth: true }`.
  - Frontend preview running on `http://127.0.0.1:3602/#/`.
  - Visual artifacts: Captured 9 full-page desktop/mobile screenshots in `final-presentation-screens/`.
- **Limitations**:
  - Guest mode is client-side in-memory only; does not write to hosted Supabase tables or clinical registries.
  - Live patient-specialist sharing and PDF export in guest mode use synthetic templates. Real authenticated workflows require valid Supabase user credentials.
