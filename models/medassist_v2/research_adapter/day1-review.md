## Minimal Model A-to-B evidence contract

[handoff.py](handoff.py) defines **`model-a-to-b.evidence.v1`**; [JSON Schema](handoff.schema.json) mirrors it. `build_handoff` is an explicit pure projection of already validated fictional disclosures. It reuses adapter history/type/dependency validation; it never scores, fits, opens datasets or runs a Model B. It is **not wired into HTTP v1 yet**, preserving that interface. The existing `model-a.evidence.v1` remains available.

- `observed_positive`: an explicitly supplied binary `true`, not a diagnosis or severity label.
- `observed_negative`: an explicitly supplied binary `false`; never inferred from missing/default/unasked evidence.
- `observed_value`: typed categorical or multichoice content, including numeric zero, NA/default, an empty set or mixed default/nondefault members. No generic positive/negative interpretation is assigned.
- `unknown`: a disclosed question whose answer was explicitly unknown; value null, with a follow-up turn and fictional-disclosure provenance.
- `not_asked`: no disclosure, value null, no turn, `not_disclosed` provenance. A pending model question remains in this state until answered.
- `unsupported`: a known quarantined definition, value null, `quarantined_question` reason and frozen-scope exclusion provenance. Out-of-vocabulary submissions instead abstain at ingress and produce **no accepted handoff**; their text is not carried forward.
- `contradiction`: an unresolved supplied conflict, null value, retained disclosed provenance; no automatic resolution or assessment.

The projection enumerates all **223** definitions with five unsupported exclusions, never inventing 218 negative observations. Each item carries ID/type, status/value and source/disclosure/turn provenance. The envelope carries source context, protocol/contract version, developer-fictional origin, `human_clinical_review: false` and `model_b_status: not_enabled`. Absent items in partial external representations mean unspecified, never negative. Clinical output fields are forbidden. JSON Schema validates structure; only the projection/adapter can verify frozen membership, exact allowed values and chronological eligibility. A successful structural validation is not clinical validation.
