## Submission, retry and recovery behavior

- Page-memory UUIDs identify the conversation and logical extraction/interview request through HTTP headers. Original evidence contracts and Python request bodies are unchanged. The synchronous submission ledger blocks concurrent Send/Enter/double-click work before state updates. Retries reuse the first message/narrative and request ID. Accepted proposals and question transitions cannot commit twice in the same page session.
- The guarded local backend coalesces overlapping identical IDs and replays successful replies. Changed payloads under an existing ID return 409. Cache scope is one process, at most 128 entries, ten-minute expiry; it retains proposals/results in memory only, never text in cache keys or data on disk. Failed replies release the ID for recovery. Existing authored research clients without IDs remain compatible.
- A client disconnect does not discard an identified request's bounded completion/cache result. Retrying after a lost reply can recover the cached success. Process restarts/expiry are not a durable exactly-once guarantee; the demo has no durable clinical session service.
- Internal categories are `RATE_LIMITED`, `QUOTA_EXHAUSTED`, `AUTH_FAILURE`, `PROVIDER_UNAVAILABLE`, `PROVIDER_TIMEOUT`, `INVALID_STRUCTURED_OUTPUT`, `EVIDENCE_MAPPING_FAILURE`, `EMPTY_MODEL_A_CANDIDATES`. Friendly UI wording avoids raw errors. Empty candidate pools retain the existing graceful stop and receive an internal outcome header.
- At most one automatic retry is allowed for transient 429/408/5xx/network failures inside the same 15-second overall provider deadline. Retry-After takes priority; waits longer than two seconds defer to manual recovery. Otherwise bounded exponential backoff with jitter applies. All actual attempts count toward the unchanged application caps: four/minute, twenty/process. Auth/payment/explicit exhausted daily allowances never retry automatically and remain blocked for operator correction.
- Manual transient retry honors the returned cooldown and keeps accepted evidence/current question unchanged. Invalid output permits one explicit retry and then closes the repeated-input loop. Mapping/unsupported wording retains bounded clarification. Confirmation is still explicit; normalization never accepts evidence itself.
- Refresh deliberately clears page-memory fictional state rather than silently saving medical narratives or replaying pending requests. The scope notice explains this. Restart creates a fresh session. Emergency interruption remains independent of cloud availability and invalidates stale pending results.
- Development-only `/api/research/model-a/language/diagnostics` contains bounded status/latency, request correlation, numeric token usage, sanitized rate headers, finish reason, validation code and allowlisted limit dimension. It contains no input text, authorization, key, reasoning text, raw provider error body or private artifact path. The route inherits loopback/host guards and is absent in production.
