## Root causes and bounded changes

The [pre-repair audit](emergency-phase2-audit.md) separates lexical coverage from context and precedence. Previous fixed-order patterns missed reversed anatomy/qualifiers and conversational paraphrases. Broad negation could apply to a different finding; history and time cues did not resolve recent stopped warnings; subject detection missed possessives and affected-person objects. Educational/hypothetical scope could leak between statements. The previously established emergency latch worked for recognized triggers.

Added `provisional-rules.v3.json` (`emergency-context.v3.0.0`) without changing v1/v2. TypeScript and Python now use expanded bounded warning grammar and explicit normalization; mention-local prefix/inside/suffix negation with intrinsic inability handling; relative-time/counterfactual context; limited antecedents; body-part/bystander and affected-object subjects. The backend evaluates each prior/current utterance independently and retains the highest-priority interruption, preventing an older educational statement or later denial from masking a separate current emergency. This is deterministic heuristic processing, not clinically validated language understanding.

The safety-decision.v2 API and three actions remain unchanged. Clarification suppresses ordinary extraction without creating negative evidence or consuming Model A questions. Established emergency guidance remains latched through outages, pending/late replies, repetitions and corrections; only explicit fictional restart resets software state. No generic condition mention alone qualifies as an active emergency. No symptoms or diagnoses are inserted into Model A evidence by the guard. Existing Material Web UI, eight-question wrapper, evidence contract, provenance, UNKNOWN and location consent remain unchanged; no UI/CSS redesign.
