# Component ownership and orchestration

The existing React conversation calls the guarded Express boundary. `GroqProvider` in `server/medassist-ai.ts` delegates to the qualified canonical Groq transport and locks `qwen/qwen3.8-27b`. It records counts/timing and bounded allowlisted rate-limit metadata in memory, without retaining medical text or credentials. Nothing is logged or added to browser responses. The existing provider owns fixed HTTPS, strict extraction, finite response limits, cancellation, quota latching and no fallback.

Validated language output remains an unaccepted proposal. Missing, explicit UNKNOWN, absent, contradictory and unsupported information stay distinct. Existing explicit user confirmation produces the unchanged structured interview request; no LLM or disease model selects follow-up questions.

With the modular flag enabled, the existing loopback Python endpoint calls `MedAssistOrchestrator.interview`, which delegates to `ModelAAdapter` and the canonical `research_adapter.demo.interview`. That function alone invokes the verified Model A service and unchanged handoff builder. The wrapper validates complete export size and canonical schema/provenance; catalogue membership, types, conditional eligibility and repeats remain enforced by the frozen service. IDs are catalogue-owned, not inferred from a contiguous numerical range. No encoder, ranker or protocol is forked.

`research_summary` is a separate developer-only Python method, not wired into chat or HTTP. It revalidates evidence, copies it for each optional component and isolates disease/Model B failures from the independent safety seam. The disease model is optional and disabled, not a prerequisite for questioning or urgency. Safety cannot consume or be overridden by disease predictions or LLM instructions. Hospital search accepts only the existing versioned scoped-consent/location shape (expiry in Unix milliseconds), rejects narrative fields and performs no network request.

`EvidenceHandoff`, `NextRequest` and `DemoResult` are imported from their canonical existing modules. The 223-item `model-a-to-b.evidence.v1` contract is unchanged. A separate `medassist.ai-proposal.v1` wrapper marks Python-only sparse proposals unaccepted; it is not an alternate A-to-B contract. `ModelRegistry` contains immutable metadata references, not loaders or authorization. Component imports have no model-deserialization side effect.

The new Model B result contract supports four technical target slots and independent unable-to-assess. Slot names deliberately carry no clinical action/threshold mapping: the blueprint requires qualified prospective label definition. `DisabledModelB` always returns unable-to-assess with no urgency, version or validation claim. The contract's future research-assessment branch requires explicit version, provenance and validation metadata; no executing implementation is supplied.

The frontend and existing route names/authentication remain unchanged. There is no competing backend, no new background process and no patient-facing disease output. The optional composition switch is development-only because the existing enclosing routes remain development-only. This is maintainable research architecture, not verified production access control or clinical readiness.
